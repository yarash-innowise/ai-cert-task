# Epic-01 User Management & Authentication - Implementation Plan

## Goal

Build Epic-01 as one server-rendered, framework-free PHP 8.4 application (Twig UI + backend, PostgreSQL 18, Phinx, PHPUnit 12, PHPStan level 8, PHP-CS-Fixer) in modules `Shared`, `Identity`, `Organization`, `Onboarding`, `Family`, `Approval`, `Availability`, `Admin`, `Integration`, so that all of AC-1..AC-89 and the spec edge-case table are met or explicitly evidenced.

- Spec (authoritative, what/why): `specs/requirements-analyst-user-management-auth-spec.md`
- Design (how, components C1-C18, decisions D1-D25): `specs/architect-user-management-auth-architecture.md`
- Approved 2026-11-12 by the user: spec, design, G1 (parent sets child login), G5 (audit = IDs + business name), G7 assumptions.
- Task id: `epic-01-user-management-auth`; plan lives in `tasks/TASK-001/` (counter set to 2).

## How to run checks (Docker only; no host PHP)

```
docker compose up -d db mailpit
docker compose run --rm app composer install
docker compose run --rm app vendor/bin/phinx migrate              # dev DB `app`
docker compose run --rm app vendor/bin/phinx migrate -e testing   # test DB `app_test`
docker compose run --rm app vendor/bin/phpunit                     # all suites
docker compose run --rm app vendor/bin/phpunit --testsuite Unit|Integration|Http
docker compose run --rm app vendor/bin/phpunit --filter <pattern>
docker compose run --rm app vendor/bin/phpstan analyse            # level 8
docker compose run --rm app vendor/bin/php-cs-fixer fix --dry-run --diff
docker compose run --rm app php bin/console <command>
```

Host ports (task 1 deviation, ports 80/443/8025 taken locally): app https://localhost:18443 (http 18080), Mailpit UI :8125, SMTP :1125; in-network SMTP stays `mailpit:1025`. All overridable via env.

Aliases used below: `PU` = `docker compose run --rm app vendor/bin/phpunit`, `STATIC` = phpstan + php-cs-fixer dry-run. Every task is only done when `PU` for its filter, plus `STATIC`, pass; the whole `PU` run must stay green after each task. Mark `[x]` only after that.

Conventions for every task: `declare(strict_types=1);`, PSR-4 under `App\`, PDO prepared statements only, tenant repositories take `OrganizationId` (D8), side effects go through the outbox (D12), new tests are written in the same task as the code, each Http test goes through the full middleware pipeline, an `AC-n` tag is put in the test method name or `@group AC-n` so a task's check can be run by `--filter`/`--group`.

Roll-back note: every task is one revertible commit; each migration has a `down()` and is expand-only (new tables/columns), so reverting a task never needs a data backfill.
